## 3. P6 实施内容

### 3.1 请求产生与运行身份

在上游判定应执行 AfterTask 的生产结果路径接入协调，保留成功、失败、手动停止、仅启动/连接等分支的原语义。任务按钮被点击、队列变空或 UI 提前变成空闲，都不能作为新增自动请求的依据。

每个请求保留来源实例、实际 runId、动作以及必要的目标/配置身份；同一运行的重复回调只能产生一次有效请求。通知、任务状态、普通停止回调和 CLI 的等待语义继续可用。

请求产生与实际执行是两个时点。当前 `HandleAfterTaskOperation()` 在停止结果处理中触发，此时运行链可能还没有释放实例/资源；不能直接在这个回调里关机，也不能提前释放占用来满足条件。等待实际清理完成后再重新判断执行。

手动取消不新增请求，但也不能删掉其他已经正常完成的运行产生的有效 pending。实例关闭或页面切换后，不依赖已释放 ViewModel 去读取请求动作或目标；局部目标已不存在时跳过并记录，不回落到当前活动实例。

### 3.2 全局空闲判断与最终执行预约

利用 P4/P5 的真实事实来源：普通运行的实际启动/运行/停止状态及 `RunCompletion`，`CompatibilityTimerRuntime` 的预约，`ResourceAccessCoordinator` 的实际占用，以及 `RecordingSession.Completion`。

- 全局关闭/重启程序、系统关机/重启等待所有相关实例启动、执行、停止清理和录制占用释放。不能只检查 `TaskQueue.Count`、`IsRunning`、当前 ActiveTab 或最后一个完成实例。
- 录制 `IsQuiescent` 仅表示原生操作已停，不等于占用已释放。保存失败、取消结束、真正停止失败仍可能占用；自动结束应继续等待，不能为了执行 pending 强制关闭录制或绕过保存决定。
- 有效占用/预约释放时重新评估 pending，即使最后释放的是录制，或其 AfterTask 为 None，也不能让已有请求永久搁置。
- 处理普通强制定时、跨配置定时及 CLI 强制重启的“旧运行释放 → 新运行准入”窗口。旧运行的取消不触发旧 AfterTask，重启请求仍有效时不能在交接空隙执行全局动作；失效/取消的预约也不得永久阻塞 pending。
- 最终“仍无占用”的核验与取得执行资格必须和正常启动准入处在一致的协调边界。取得全局执行资格后不能又放行新的任务/录制；资格失败则重新等待。不要持有同步锁跨越 UI 对话框、异步设备清理或系统动作。

具体通知和协调方式由你结合现有代码判断，不要求新建一套运行状态机。若需扩展共享入口，修改必须服务于上述真实行为，并补对应生产路径回归。

### 3.3 动作合并、优先级及一次性关机

固定 fork 的全局动作优先级如下，本轮应保留；`ShutDownOnce` 按关机级别参与：

| 动作 | 优先级 |
|---|---:|
| ShutDown / ShutDownOnce | 50 |
| RestartPC | 40 |
| CloseEmulatorAndRestartMFA | 30 |
| CloseEmulatorAndMFA | 20 |
| CloseMFA | 10 |

同优先级使用稳定顺序，沿用旧 fork 保留先到请求的行为。一次合并批次只提交一次胜出的全局动作，不遍历执行所有关机/重启/退出请求。保留参与请求身份，用于一次性标记及正确收尾。

`CloseEmulator` 是实例局部动作，按原语义处理，不能因为全局协调而错误作用于别的实例。包含关闭目标软件的组合动作仍绑定其请求目标，不顺手关闭所有实例的软件；目标已消失时不得改为关闭 ActiveTab。

`ShutDownOnce` 入队时不清空。只有真正提交关机执行时，才清除本次参与并被满足的一次性标记；正确处理多个实例同批参与，以及设置写入失败/执行提交失败的可观察结果，避免静默消耗或重复提交。不能覆盖用户后来保存的其他 AfterTask 值，也不能因切换命名配置而清错来源配置。实现记录要说清标记消费时点、参与者和失败处理，不声称可以等真实断电后才确认消费。

pending 只存在于本进程，不持久化为下次启动要执行的关机请求。不要创建无限自动重试破坏性系统动作的循环；执行失败应有明确结果及适当的资格释放处理。

### 3.4 保留显式操作与 CLI 契约

全局协调入口应限定为自动 AfterTask，不能简单把公共 `ShutdownApplication` / `ShutdownSystem` / `RestartApplication` 等所有调用都改成“等待全部实例”。检查它们的真实调用方，保留手动退出、特殊任务、更新/重启等已有显式语义。

CLI `--quit-after-run` / `-q` 继续等待它成功准入的目标运行完成；启动被拒绝时不等待或退出其他运行。CLI 强制启动仍先结束旧任务/录制，并尊重录制保存取消及真实停止完成。对自动 AfterTask 与显式 CLI 退出同时出现的路径明确区分请求来源，避免误吞 CLI 退出或误把手动取消变成新的自动请求。
