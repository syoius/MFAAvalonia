## P4-R1 / P1：普通定时的强制启动只停止旧任务，没有启动新任务

触发：使用上游普通定时规则（`FixedInstance=false`），勾选强制启动，实例已有运行任务。这是现有界面可创建的规则；迁移规则的固定实例调度路径与此不同，不能只以固定实例测试代替。

调用链：

1. `MFAAvalonia/ViewModels/Other/TimerModel.cs:382` 仍调用 `vm.StopTask(vm.StartTask)`。
2. P4 的 `MaaProcessor.StopAndWaitAsync()` 在停止命令内调用 `HandleStopResult(..., action, ...)`（`MFAAvalonia/Extensions/MaaFW/MaaProcessor.cs:4561`）。后者通过完成提示逻辑调用 `action`，测试替身分支也保持这一时点。
3. 此时 `RunTaskChainAsync()` 仍在等待停止完成。实例及资源占用到 `MaaProcessor.cs:3583` 起才释放，`IsTaskRunActive` 到 `:3587` 才清零。
4. 停止回调中的 `StartTask()` 因旧运行仍占用实例被拒绝。之后旧运行退出，没有任何重启重试。

独立复现使用实际 `TimerModel.ExecuteAction()`、`TaskQueueViewModel`、`MaaProcessor`、MFATask 队列与停止回调；仅设备执行/停止及通知使用既有替身。结果：

```text
OBSERVED force timer: beforeRun=1; afterRun=1; deviceExecutions=1; active=False
```

预期旧任务停止且清理结束后，第二次运行被准入；实际停在空闲状态。该结果由回调与释放的固定顺序决定，不依赖毫秒级竞争。

修复范围：让“停止后启动”的普通定时路径等待对应旧运行真正完成，再尝试启动；可复用本次已用于 CLI 的 `RunCompletion` 语义，或调整停止回调契约并适配其真实调用方。不能通过提前释放占用或固定延时绕过生命周期保护。仍需尊重规则禁用/编辑、实例关闭或其他运行已接管等现有时效条件。

补测应通过真实普通定时入口验证强制停止→实际清理完成→再次准入；同时保留延迟停止期间拒绝新启动/资源写入的已有断言。无需重写调度器或执行引擎。

## P4-R2 / P2：全局启动忽略“只启动脚本”的软件启动边界

触发：实例启动设置为 `BeforeTask=StartupScriptOnly`，通过全局启动执行；这是 `StartSettingsUserControlModel.BeforeTaskList` 提供的选项。

改动前 `GlobalStartManager.StartInstance()` 只在设置包含 `StartupSoftware` 时调用 `StartSoftware()`；脚本模式不启动软件。P4 将这一操作移入已准入队列，方向正确，但条件变宽：

- `MFAAvalonia/Extensions/MaaFW/MaaProcessor.cs:3656`：所有来源为 `Global` 的运行均入队 `WaitSoftware()`。
- 同文件 `:4794`：`WaitSoftware()` 用 `Contains("Startup")` 判断是否启动软件，包含了 `StartupScriptOnly`，继而在 `:4798` 调用 `StartSoftware()`。

因此，已配置软件路径的用户选择“只启动脚本”，全局启动仍会尝试打开程序并进入软件启动等待流程。原首启分支已经区分 `StartupScript` / `StartupSoftware`，全局分支没有保留同样的语义。

隔离复现使用实际 `TryStartTask(source: "Global")` 及生产队列，设置 `StartupScriptOnly`，将软件路径留空并将设备/通知替换为离线行为。通过仅由 `StartSoftware()` 创建的 `_emulatorCancellationTokenSource` 观察调用：

```text
OBSERVED Global + StartupScriptOnly: StartSoftware state before=False; after=True
```

空路径保证审查不会打开外部程序；这里证明的是不应发生的软件启动方法调用。非空路径会进一步进入原有 `Process.Start` 分支，由代码调用链确认。

修复范围：保留操作在已准入队列内执行，同时准确区分 None、StartupScriptOnly、StartupSoftware、StartupSoftwareAndScript；软件启动判断应依据现有设置语义，而不是宽泛的字符串前缀。为真实 Global 队列补充脚本模式和软件模式断言，不需要新增启动策略框架。
