# 当前分支与上游最新主线差异及同步评估

分析日期：2026-09-19（Asia/Shanghai）。本文只做静态分析、历史对比和临时仓库中的合并预演；没有修改业务代码、切换当前分支、实际合并、运行程序或发布版本。

范围更新：根据后续要求，**本轮只实施桌面端同步，不迁移、定制或改进 Android 应用端，也不安排 Android 后续阶段、构建发布和验收工期**。桌面历史配置迁移仍在范围内；桌面通过 ADB 控制 Android 手机/模拟器也仍在范围内。可执行的工作拆分、转换规则和验收门槛见配套[桌面端上游同步实施方案](./桌面端上游同步实施方案-2026-09-19.md)，实施细节以该方案为准。

已确认的交付约束：新 GUI 首次启动应**自动、无损迁移**旧数据，不要求普通用户手动整理配置；已有用户使用的**同实例跨配置定时**必须保留。今后对外发布仅为 **Windows x64（`win-x64`）和 Apple Silicon macOS（`osx-arm64`）**。本仓库的 **`syoius/MFAAvalonia` / `YuanMFA` 是 GUI 构建产物层身份**；由 MaaYuan Action 组装最终包，用户沿 **`syoius/MaaYuan` / RID `MaaYuan`** 按资源版本更新，不新增独立 GUI 更新入口。自动全局结束操作等待所有实例及录制占用释放，手动取消不产生新的自动结束请求。这些是后续实现要求，本次未实现或验证。

## 1. 结论与比较边界

**建议以最新上游为技术底座，按功能移植当前分支的产品定制，并专门开发旧数据迁移。** 如果需要保留现有分支的 Git 继承关系，可以在合并提交中采用相同的实现策略。重点是选择上游的新架构，再接回独有行为，而不是保留两个配置系统或逐行拼接两个任务调度实现。

当前真正需要重点保留的内容包括：

- MaaYuan 抄作业工作流，以及 9 月新增的 Copilot 任务与主页任务独立存储、独立执行。
- 面向游戏动作和回合的作业录制、编辑、SP 解析及导出服务接入。
- 当前完整实例导入导出、实例级定时规则及“定时前切换到另一配置”的自动迁移和行为兼容。
- 多实例结束后操作的全局延迟执行策略，避免一个实例结束就关闭仍在执行其他任务的程序或系统。
- 总控台内嵌启停、当前任务与进度、竖屏布局，以及 MaaYuan 品牌和发布渠道。

上游新增内容已远超“小版本修复”：包括配置与标签体系重构、Project Interface 扩展、特殊任务、多 Agent 与生命周期改进、实时截图流水线、更新器重构、诊断能力、Android 原生运行能力等。完整同步的主要成本是**行为与数据迁移**，不是依赖版本号修改。

## 2. 已经共有、无需重新开发的基础能力

共同基点已经具有多实例基础、实例标签、总控台基础页、ADB/Win32/PlayCover/Gamepad 控制器、Interface V2.2.0 相关适配、任务选项生成、Focus 协议、定时能力、实时画面、MirrorChyan 更新、国际化和可配置布局等。

因此，“多实例”“总控台”“Agent”“定时任务”“录屏/调试开关”不能笼统列为任意一方全新功能。需要区分：多实例之后如何存储配置、Agent 是否支持多连接及上下文、定时规则由谁持有、录制的是框架调试数据还是 MaaYuan 游戏作业。

同样，当前已经是 .NET 10 / C# 14；此次同步不是一次 .NET 大版本迁移。每日/每周/每月定时类型也已存在，上游新增重点是调度模型、可增减规则和操作类型。

### 3.1 抄作业的实际耦合点

主要实现位于 `CopilotViewModel.cs`、`CopilotView.axaml(.cs)`、`CopilotTaskFactory.cs`、`LikeHistoryHelper.cs` 和 `GridLengthStorage.cs`。[F-COPILOT] [F-FACTORY]

当前下载接口采用主站 `https://share.maayuan.com`、备用站 `https://share.maayuan.top`。录制导出接口为主站的 `/simingapi/api/export`。本次只检查调用代码，没有访问业务接口、上传录制或验证后端可用性。

迁移需要保留三个不同的数据边界：

1. **资源定义**：来自 `MaaProcessor.Interface`，作为创建默认任务的输入；不能被主页控件编辑污染。
2. **实例 Copilot 状态**：`ConfigurationKeys.CopilotTask` 保存重复次数和选项，执行时再克隆；不能与主列表共享可变对象。
3. **已加载作业文件**：实际写入当前资源路径下的 `pipeline/copilot`，多个实例可能共用，不是给每个实例保存一个字段就实现了文件隔离。

`620efca3` 还在 `TaskLoader.LoadTasks()` 开头克隆资源任务定义。升级时应追踪新版 loader 是否仍会修改定义，保留这个不共享可变状态的保证，不能只移植一个工厂类。[F-LOADER]

当前 Copilot 的选项界面在 code-behind 中自行创建 switch/select 等控件。上游已增加 checkbox、hotkey、全局/控制器/资源选项和统一选项布局。继续维护复制出来的旧控件生成逻辑会逐渐与主页面不一致。可利用上游 `TaskOptionGenerator(viewModel, saveConfigurationAction)` 的现有回调入口生成控件，把保存回调绑定到 Copilot 独立状态；仍需检查生成器内部是否依赖主页选中项。[U-OPTIONS]

此外，`CopilotTaskFactory` 使用固定名称 `✨ 自动抄作业V3` 及其本地化显示名定位任务。若资源定义改名，功能会失去入口。适配时宜保留旧名称兼容，并考虑资源侧提供稳定的任务标识；这属于可选改进，不是本次已经实现的功能。

### 3.2 录制不是通用键鼠录制

当前录制器使用游戏特定动作模板、坐标、回合和 SP token，通过 `tasker.Click/Swipe/AppendTask` 执行动作并记录步骤。开始录制时记录实例 ID，随后通过该 ID 找回 Processor，避免切换标签后把动作发给另一个实例。[F-RECORD]

这使桌面迁移相对集中，但有两个边界：

- 新版控制器分辨率配置、Tasker 回收、并发运行和停止行为必须与录制动作兼容；不能只验证界面能打开。
- 本轮只接入桌面 `RecordingOverlayView`，不移植 Android 系统悬浮窗，也不开发移动端录制界面。

### 3.3 不要遗漏“结束后操作”这项原创行为

`ca7d985b` 的标题是“多实例下禁用 beforetask 设置”，但代码不仅调整了界面，还加入了 `AfterTaskLock`、`PendingAfterTask` 和全局操作延迟执行。只看提交标题会漏掉这一项。[F-AFTER]

当前优先级为：关机 > 重启系统 > 关闭目标并重启 MFA > 关闭目标并关闭 MFA > 关闭 MFA。上游最新版本增加了 `ShutDownOnce`，也修复了任务成功、失败后执行结束操作的时机，但没有相同的跨实例 pending 聚合。[U-AFTER]

用户已确认保留全局协调语义：等待所有实例及录制占用释放，手动取消不新增自动结束请求。运行判断覆盖“正在启动、正在执行、正在停止、录制”，不能仅用 `TaskQueue.Count > 0`。一次性关机标记在真正执行时消耗、已有 pending 的有效性及关联实例关闭等实施细节见配套方案第 7 节，仍需行为验收。

## 5. 同步的关键技术难点

### 5.1 配置文件迁移：最高优先级

当前模型与上游模型不同：

| 维度 | 当前分支 | 最新上游 |
|---|---|---|
| 实例保存位置 | `config.json` 或 `mfa_*.json` 中的 `Instance.{id}.{key}` | `config/instances/{id}.json` 中直接保存实例字段 |
| 实例与配置关系 | `_instanceConfigMap` 与全局 `Instance.{id}.Config` 映射 | 以独立实例文件为中心，旧配置迁移为实例 |
| 历史键兼容 | `Instance.*`、`instance.*` 及小写旧键、无前缀 fallback | 已有迁移器，但关键提取路径使用 `Instance.` 前缀和实例字段白名单 |
| Copilot 独立状态 | `CopilotTask` 是实例字段 | 上游无此业务字段 |
| 定时 | 每实例 TimerModel / 8 槽 | 全局 TimerModel / 动态规则，指定实例 ID |
| 完整导出 | JSON：`version/sourceInstanceId/sourceConfig/data` | 分享文本：`<项目>://mfa-instance-sharing/v1/<实例名>/<压缩数据>` |

上游**并非没有旧数据迁移**，已经提供 `MigrateLegacyConfigs()`。但不能未经验证直接认为它支持当前 fork：[U-MANAGER]

1. `MigrateScopedKeysToFiles()` 通过 `ConfigurationKeys.IsInstanceScoped()` 白名单筛字段。必须在运行迁移之前注册 `CopilotTask` 等 fork 字段，否则不会随实例数据迁移。
2. 当前分支会读取小写前缀；上游关键迁移路径的 `StartsWith("Instance.")` 不提供同等兼容，需要补充大小写和旧字段归一化。
3. 上游迁移剩余 `mfa_*.json` 时，会将文件中的 scoped key 去前缀，使用第一个同名字段创建一个新实例。若一个旧文件中含多个实例的数据，直接沿用此路径可能合并掉实例差异。
4. 当前实例到配置文件的映射必须参与解析；不能只迁移“当前 config.json”，也不能把所有 `mfa_*.json` 都当成“一文件恰好一个实例”。
5. 上游迁移成功后有移除旧字段、删除旧配置文件的行为。正式迁移需要先备份原始文件并验证结果，不能依赖旧版程序直接读取新版配置来回滚。

推荐技术路线：**新 GUI 首次启动自动检测 → 原件备份 → 旧格式读取器 → 中间实例/配置快照 → 新版实例文件 + 全局调度规则 → 校验与迁移标记 → 正常加载**。保留稳定 ID 或记录 ID 映射，迁移应可重复执行且不重复创建实例/定时器；先写暂存文件，再通过 journal 完成切换，失败恢复一致状态并保留原数据。在第一次会写配置的初始化、首启模板和任何实例/定时/自动启动之前执行，不要求用户导出导入、编辑 JSON 或重建定时。

迁移清单至少包括：实例名称与排序、控制器/资源选择、任务顺序和选项、Copilot 状态、重复次数、定时及强制启动选项、开始/结束设置、共享配置范围和必要布局数据。作业缓存、录制文件和点赞历史属于另一组目录/配置文件，也要纳入备份与路径核对。

跨配置定时已确认有人使用，属于必做兼容：旧规则的目标是配置名，上游目标是实例 ID，不能直接复制。将旧配置转换成绑定同一实例的命名快照，保留前 2 分钟预切换、规则级强制启动、配置编辑和切回行为；不为每份配置创建争用同一设备的新运行实例。迁移后可直接继续使用和编辑规则，具体映射、错过窗口及冲突处理见配套方案第 4.3 节。

成功路径只需显示简明进度与完成摘要；失败时提供重试/恢复入口，阻止半迁移状态启动任务。“无损”需用有效值、引用和相关文件内容比较证明，不等于仅有备份或数据能反序列化；原本损坏或缺失的数据需保留诊断，不能声称可自动补全。

### 5.2 导入导出：同名功能不代表相同协议

当前 `.mfa-instance.json` 保存完整实例 `data`，上游 `InstanceConfigSharePayload` 明确列出的内容主要是任务、控制器/资源名称及 global/controller/resource options，并不自动包含 fork 的 Copilot、完整设备连接信息和实例级定时。[F-PROFILE] [U-SHARE]

可用方案：

- 默认分享沿用上游格式，获得项目名校验、版本号与压缩文本能力。
- 同时保留“完整实例备份/导入”入口和旧 `.mfa-instance.json` 读取，映射到新 schema。
- 若要只维护一个新格式，需要增加明确版本及扩展段；不能悄悄把“完整备份”退化为“仅分享任务”。

### 5.3 任务执行、停止与状态

上游已使用 `TryBeginTaskRun()` / `IsTaskRunActive`、命令队列、每任务运行状态、失败/取消区分和截图 Tasker 代际控制。旧的“队列非空代表运行中”无法覆盖启动和停止窗口。[U-PROCESSOR]

Copilot 可以继续通过上游现有的 `Start(List<DragItemViewModel>, ...)` 提交单任务快照，无需另建一套执行引擎。但需要核验：输入校验与新增选项处理是否覆盖这条入口；状态 UI 是否错误映射到主页同名任务；启动时重载是否覆盖独立选项；结束后操作是否只执行一次。

进一步细化已确认：上游启动校验以主页列表为主，`FinalizeTaskRun()` 和耗时更新也仍遍历 `TaskItemViewModels`。独立 Copilot 快照需要接入“实际运行集合”，不能仅改通 `Start()` 调用；其 `void` 返回及停止时 UI 先恢复空闲的行为，也要求单独处理启动接受与后台占用释放。具体接入点见配套方案第 5 节。

录制使用的 `GetTaskerAsync()` 与原始 `Click/Swipe/AppendTask` 也必须纳入实例占用和取消策略，避免与普通任务、资源重载或截图 Tasker 回收相冲突。建议增加很薄的实例操作适配层，保持业务页面不依赖 Processor 内部生命周期细节。

### 5.4 作业资源是共享可变文件

当前资源锁以资源名称和 `TaskQueue.Count > 0` 判断。加载作业时会清理活动目录中的 JSON/JSONC（保留 `copilot_config.json`），再复制文件并重建资源。[F-COPILOT]

迁移最小方案是：保留共享目录规则，统一解析实际资源路径，以新版运行状态判断是否可写，重新检查后完成文件替换与重载。应覆盖“两个资源名指向同一路径”的情形。

长期方案是每实例保存独立作业覆盖层/工作目录，再通过资源加载策略接入。它能支持不同实例同时加载不同作业，但需要额外处理资源搜索优先级和 Agent 读取路径，属于功能扩展，不应作为完成首轮同步的前提。

### 5.5 总控台、进度与内存

保留上游的独立截图 Tasker、帧获取和生命周期控制，再补回内嵌启停、竖屏模式、任务名称和进度展示。进度应明确统计主任务而不是连接、预处理等辅助任务；尽量使用上游任务状态事件汇总，避免重新耦合 `_mainTaskTotal` 和队列内部结构。

没有文本冲突的独有页面仍可能出错。例如新版 Bitmap 释放规则、实例惰性加载、日志集合和选项面板布局变化，都可能改变旧页面的运行行为。至少验证页面切换、后台实例、关闭标签、断线重连和持续截图时的内存趋势。

### 5.6 发布与更新链路

**校正此前结论：保留独立 GUI 更新方法，不等于用户正在使用该更新通道。** 当前及固定上游均隐藏 GUI 更新通道、自动更新开关、检查和更新按钮；启动检查中的 GUI 更新分支也被注释。正常用户按资源版本更新，这一产品模式没有因上游同步而改变。[F-UPDATE-UI] [U-UPDATE-UI] [F-UPDATE] [U-UPDATE]

本机 `C:\MaaY` 对应 `syoius/MaaYuan`，本次补查固定到 `5684509e5cfdc0de90d42d29c36373a453848357`；所引打包/配置文件无本地修改，不宣称该 SHA 是远端最新版本。其链路为：[Y-PACK] [Y-INTERFACE] [Y-INSTALL] [Y-MIRROR]

| 阶段 | 已核验行为 |
|---|---|
| GUI 产物 | `syoius/MFAAvalonia` 发布 `MFAAvalonia-*`，主程序名为 MaaYuan；本仓库 MirrorChyan `YuanMFA` 属于此层 |

因此不应把普通用户更新改为 `syoius/MFAAvalonia` / `YuanMFA`，也无需新增独立 GUI 更新入口。底层残留 GUI 方法仍用 `MFAAvalonia` / 默认 owner 是事实，CDK 查询也用此标识，但不能据此推出正常资源更新会下载通用 GUI。此前预设“旧客户端无法到达新 GUI 渠道”的风险及固定增量撤回。
