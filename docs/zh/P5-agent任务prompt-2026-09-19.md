## 3. P5 实施范围

### 3.1 桌面入口、旧业务及文件兼容

恢复并适配旧 fork 的 `RecordTaskViewModel`、`RecordTaskView.axaml(.cs)`、`RecordingOverlayView.axaml(.cs)` 所承担的桌面功能，接入当前导航、实例及 UI 架构。先确认现有实现和可复用能力，再决定必要文件改动。

保留原有游戏动作模板、坐标、回合编辑、旧 token / 通用 SP 解析、录制文件及导出结构。支持旧录制读取、继续编辑、保存后重载。保留未知或无法解析数据的可恢复信息，不静默丢弃或写成默认值。

本轮不增加通用键鼠捕获、移动端录制、新后端协议、每实例独立作业覆盖层或全新 UI 体系。

### 3.2 固定会话目标与实际占用

录制开始时固定实例 ID、实际资源路径及代际、控制器目标。录制动作、日志和悬浮窗始终使用这个目标；切换 ActiveTab 不得把操作发给另一个实例，也不得在目标消失后回落到当前实例。

复用 P4 已有 `MaaProcessor`、`CompatibilityTimerRuntime`、`ResourceAccessCoordinator` 的生产入口与占用事实，按需做必要的小范围接入：

- 同实例正在连接、启动、执行或停止时，明确拒绝录制，或按现有语义等待其真正结束后重新核验准入；不能观察一次 Idle 就开始向设备输入。
- 录制获得实例操作资格及实际资源使用资格之后才能调用控制器。录制会话和未完成动作占用应可被其他生产入口观察到。
- 同实例主页、Copilot、定时、CLI、全局启动等路径不得与录制并发输入；共享资源的 Copilot 激活、卸载、配置/资源切换不得越过录制占用。
- 定时预约/强制启动、关闭实例、重连或资源切换涉及录制时，遵守统一停止及保存语义；未完成动作和资源占用释放前不能覆盖目标。若需要用户决定保存/放弃，应沿用现有交互；取消不得当作已经安全释放。
- 不把资源使用互斥扩大成无依据的全局串行。不同实例原有合法并发能力继续保留。
- 旧会话回调不能更新新会话、重绑后的目标或其他实例。

不要通过另起一套独立布尔标记绕过现有准入，也不要为录制重写整个执行引擎。

### 3.3 动作执行、取消与悬浮窗生命周期

继续复用 Click / Swipe / AppendTask 及现有动作结构，串行处理录制动作。执行失败或取消必须准确反馈，不得无提示地记作已成功执行；区分用户编辑的动作数据和实际设备执行结果。

核对当前 MaaFramework binding 的真实 API，处理 `AppendTask(...).WaitFor(...)` 等等待及其停止路径。取消等待和停止原生 job 是不同事件：关闭悬浮窗、停止录制、关闭目标实例时，应请求停止未完成操作并等待真实结束，再释放实例/资源占用。不能靠直接 Dispose 仍在使用的 Tasker 或仅取消外层等待冒充停止完成。

初始化失败、动作失败、取消和重复关闭均应收敛；重复关闭不应重复操作已释放对象。若底层未能安全停止，保留阻止危险后续操作的事实和明确提示，不谎报空闲。

保留未保存录制的保存/放弃/取消交互。切页和悬浮窗关闭后处理相应订阅及对象所有权；实时画面复用上游截图机制，不另建录制专用截图循环。窗口置顶、缩放和坐标转换依两平台实际能力验证，不宣称所有控制器、分辨率通用。

实例复制和普通配置导入不复制正在录制的运行状态，也不把会话与原生句柄序列化为配置。

### 3.4 本地保存与导出

本地录制先可靠保存，再执行导出。保存失败保留当前数据并可重试；导出失败或取消不损坏已保存本地内容。历史文件重载后有效动作、回合、SP 等数据与旧行为保持兼容。

沿用已有导出协议和主站接口，不擅自承诺备用导出接口。使用离线样例及模拟响应验证序列化、错误与取消；本轮不向真实服务上传录制、发布内容、点赞或执行其他外部写入。

## 4. 验证与 G5 证据

测试必须经过生产录制模型/会话、命令及实际占用接入。设备和网络副作用可以替换，但不能仅重复测试 P4 的模拟录制租约，更不能另写一份模拟实现作为本轮录制完成证据。

依据实际改动覆盖以下行为，采用足够证明风险的用例，不追求测试数量：

- A 实例开始录制后切到 B，动作仍发往 A；A 关闭、重连或资源代际改变后，不误发 B，也不让旧回调污染后续会话。
- 录制与同实例普通任务/Copilot/定时启动互斥；延迟停止期间新启动和共享资源写入仍被拒绝，真实结束后正常恢复；检查实际生产调用方。
- Click / Swipe / pipeline 动作按序执行，成功、失败、取消及初始化异常均有正确记录；pipeline 停止尚未完成时关闭页面或悬浮窗不会提前释放占用。
- 未保存退出的保存/放弃/取消、本地写入失败后重试、旧录制加载与往返、旧 token / 通用 SP、回合编辑以及导出失败保留本地内容。
- 现有 79 组回归的有效行为继续保留，特别是普通强制定时等待清理、失效请求拒绝、全局四种启动模式和 Copilot 独立状态；不放宽断言来掩盖回归。

所有测试使用隔离数据。明确区分静态检查、headless/生产路径测试、原生资源解析、真实设备操作、原生 UI、Apple Silicon 运行和最终整包升级。没有设备、真实历史文件或 Apple Silicon 时，继续完成可独立进行的本机实现与验证，并保留具体待验收项；不能把替身或交叉构建写成原生通过，也不能仅凭这些既知缺口停止整个 P5。
